# Визуализация графа зависимостей Maven

Практическая работа по конфигурационному управлению, вариант 30.

## Общее описание

Консольная программа для визуализации графа зависимостей Java-пакетов
(формат Maven). Менеджеры пакетов и сторонние библиотеки не
используются: pom-файлы скачиваются и разбираются самой программой
(только стандартная библиотека Python: `urllib`, `xml`, `json`).

Готовы все этапы: граф выводится на языке диаграмм D2, по
параметру дополнительно выводится ASCII-дерево.

## Функции и настройки

Все настройки лежат в JSON-файле (`config.json`):

| Параметр     | Описание                                              |
|--------------|-------------------------------------------------------|
| `package`    | пакет в виде `group:artifact:version` (в тестовом     |
|              | режиме - имя пакета, например `A`)                    |
| `repository` | URL репозитория Maven (`http`, `https`, `file`) или   |
|              | путь к файлу тестового репозитория                    |
| `test_mode`  | `true` - читать тестовый репозиторий из файла         |
| `ascii_tree` | `true` - вывести зависимости в виде ASCII-дерева      |
| `max_depth`  | максимальная глубина анализа (целое число >= 0)       |

Если в конфиге ошибка (нет файла, неверный JSON, нет параметра, не тот
тип или значение), программа печатает понятное сообщение и завершается
с кодом 1.

Модули:

- `src/config.py` - чтение JSON и проверка всех параметров;
- `src/maven.py` - получение прямых зависимостей из pom;
- `src/repo_file.py` - чтение тестового репозитория из файла;
- `src/graph.py` - `build_graph` (BFS без рекурсии, глубина, циклы) и
  `find_reverse_deps` (обратные зависимости тем же обходом по
  перевёрнутому графу);
- `src/output.py` - `to_d2` (граф на языке D2) и `ascii_tree`
  (ASCII-дерево без рекурсии, повтор пакета на пути помечается
  `(цикл)`);
- `src/main.py` - точка входа.

Тестовый репозиторий - текстовый файл, где пакеты названы большими
латинскими буквами, на каждой строке пакет и его зависимости:

    A: B C
    B: C
    C: A

Режимы запуска:

- обычный - граф на языке D2 и, если `ascii_tree` равен `true`,
  ASCII-дерево;
- `--reverse` - обратные зависимости: пакеты, которые зависят от
  заданного (`package` из конфига или `--target`). В тестовом режиме
  поиск идёт по всему тестовому репозиторию, в режиме Maven - среди
  пакетов построенного графа, в пределах `max_depth`.

## Сборка и тесты

Нужен только Python 3, сборка не требуется, сторонние библиотеки не
нужны.

    make test

или без `make`:

    python3 -m unittest discover -s tests

## Примеры использования

Тестовый режим (без интернета):

    python3 src/main.py config_test.json

Пример вывода:

    "A" -> "B"
    "A" -> "C"
    "B" -> "D"
    "B" -> "E"
    "C" -> "F"
    "D" -> "G"
    "E" -> "G"
    "E" -> "A"
    "F"
    "G"

    A
    ├── B
    │   ├── D
    │   │   └── G
    │   └── E
    │       ├── G
    │       └── A (цикл)
    └── C
        └── F

Циклический репозиторий и обратные зависимости:

    python3 src/main.py config_cycle.json
    python3 src/main.py config_test.json --reverse --target G

Три разных пакета из настоящего Maven (нужен интернет):

    python3 src/main.py config.json
    python3 src/main.py config_slf4j.json
    python3 src/main.py config_hamcrest.json
    python3 src/main.py config_beanutils.json

Текст D2 можно вставить на https://play.d2lang.com и получить картинку.

## Сравнение со штатным инструментом Maven

Для сравнения нужен установленный Maven и `pom.xml` с одной
зависимостью, например:

    <project>
      <modelVersion>4.0.0</modelVersion>
      <groupId>test</groupId>
      <artifactId>test</artifactId>
      <version>1</version>
      <dependencies>
        <dependency>
          <groupId>org.slf4j</groupId>
          <artifactId>slf4j-simple</artifactId>
          <version>1.7.36</version>
        </dependency>
      </dependencies>
    </project>

Команда: `mvn dependency:tree`. Возможные расхождения с нашим выводом:

- Maven выбирает одну версию, если пакет встречается с разными
  версиями, а программа показывает все версии как разные узлы;
- Maven берёт версии из `dependencyManagement` и из BOM, а программа
  берёт версию только из самого pom, его родителей и `properties`,
  зависимость без найденной версии пропускается;
- Maven учитывает `exclusions` и профили, программа их не читает;
- Maven в дереве показывает зависимость один раз (повторы
  пропускает), а `ascii_tree` показывает повторы, но не заходит
  внутрь пакета, который уже встречался на пути (цикл);
- у Maven в корне дерева есть сам проект `test:test:1`.
